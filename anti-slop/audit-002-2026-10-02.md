# antislop audit 002: fonts and interface text

Date: 2026-10-02
Mode: AFTER (audit first; nothing is changed until specific numbers are approved)
Scope: `frontend/src` type (families, weights, sizes, headings) and interface text (copywriting patterns).
Method: code search across `.tsx` and `.css`. Not checked in a browser for this audit.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## Findings

### MEDIUM

1. **Text smaller than 12px, against DESIGN.md's choice of larger text for older staff** (R-37, DESIGN.md Typography). Body is 15px on purpose, but form error messages and field help are 11.5px (`.field-error`, `.field-help`), small buttons 11.5px (`.btn--sm`), status tags and badges 10.5px (`.tag`, `.badge`), the sidebar count badge 9px (`.nav-badge`), the footer 10.5px, and chart axis labels 11px. Error messages matter most: they are the text a user must read to recover. Fix: 13px minimum for error, help and button text; 12px minimum for tags, badges, axis labels and the footer.

2. **Page titles use two different styles and names that do not match the sidebar** (R-02 consistency, R-31). Five pages use the older `hero-title` style in Title Case with tighter letter spacing (Dashboard, Insights, Create Visualization, Duplicate Matching, Duplicate Review Queue); the rest use `ws-page-head` in sentence case. The office Home title is 26px inline. Three titles differ from the sidebar entry that opens them: sidebar "Duplicate review" opens "Duplicate Review Queue", "Matching settings" opens "Duplicate Matching", "New visualization" opens "Create Visualization". Fix: one title style everywhere, sentence case, and each page titled exactly as its sidebar entry.

### LOW

3. **No type scale** (R-31). 22 different font sizes are in use, including half pixels (10.5, 11.5, 12.5, 13.5, 14.5), and about 140 sizes are set inline in components. Fix: a short set of size tokens (for example 12, 13, 15, 17, 22) and the inline sizes moved onto them.

4. **An unused font file ships with the app** (R-31 support). `public/fonts/PublicSans-Variable.woff2` is not referenced anywhere. Fix: delete it.

5. **Lowercase status words** (R-02 consistency). Badges read "needs review" and "pending" while every other label is sentence case. Fix: "Needs review", "Pending".

## What already passes

- Three families only, each with a written reason: Libre Franklin for headings, Source Sans 3 for body and tables, JetBrains Mono for IDs (R-06, DESIGN.md).
- Weights stay within 400 to 600; nothing at 700 or 800 (DESIGN.md).
- Uppercase is used only for sidebar group labels and table column headers, as DESIGN.md records.
- Interface text: no em dashes, no AI buzzwords (seamless, empower, unlock and the rest), no all-caps emphasis, no exclamation marks, no chatbot phrases (copywriting skill, R-02, R-16, R-36).
